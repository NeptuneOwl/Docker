# Registry & Sharing

```Docker
docker search <image>
```

searches Docker Hub for an image using the image name.

example:

```Docker
docker search nginx
```

you can also use part of the image name:

```Docker
docker search ngin
```

> NOTE
> 
> > if you use part of the name it works but expect more results as some images might have similar names

---

```Docker
docker pull <image>
```

used to pull (download) an image from Docker Hub.

you can specify the version of the image using a tag:

```Docker
docker pull <image>:<tag>
```

example:

```Docker
docker pull nginx:1.30.4
```

this pulls the specified version.

if you don't specify a tag:

```Docker
docker pull nginx
```

Docker uses the `latest` tag by default.

# Running & Controlling Containers

```Docker
docker run <image>
```

used to create and start a **new container** from an image, whether the image was downloaded from a registry or built locally.
[more_info](A.docker_run1.md) and [here](A.docker_run2.md)

---

```Docker
docker start <container>
```

used to start one or more **existing stopped containers**.

you can identify the container using:

- container name
- container ID

---

```Docker
docker restart <container>
```

used to restart one or more containers.

you can identify the container using:

- container name
    
- container ID
    

---

```Docker
docker stop <container>
```

used to stop one or more running containers.

you can identify the container using:

- container name
    
- container ID
    

---

```Docker
docker rm <container>
```

used to remove (delete) one or more containers.

you can identify the container using:

- container name
    
- container ID
    

---

```Docker
docker pause <container>
```

pauses (suspends) all processes in a container.

> NOTE
> 
> > `pause` is not the same as `stop`.
> > 
> > `docker stop` stops the processes inside the container.
> > 
> > `docker pause` freezes the processes in place while keeping the container and its processes in memory.

---

```Docker
docker unpause <container>
```

resumes the processes inside a paused container.

---

```Docker
docker kill <container>
```

forcefully stops a running container by sending `SIGKILL` by default.

similar to using the `kill` command in Linux or ending a task in Windows Task Manager.

---

```Docker
docker container ls
```

lists running containers.

you can use the `-a` flag to show all containers, including stopped containers:

```Docker
docker container ls -a
```

# Images

```Docker
docker image ls
```

lists Docker images.

you can use the `-a` flag to show all images:

```Docker
docker image ls -a
```

---

```Docker
docker rmi <image>
```

used to remove (delete) one or more images.

> NOTE
> 
> > An image is the blueprint used to create containers.
> > 
> > A container is an instance created from an image.
> > 
> > Removing an image does not automatically remove containers that were created from it, and removing a container does not automatically remove its image.

# Container Information & Interaction

```Docker
docker container inspect <container>
```

shows detailed information about a container, including its configuration, state, networking, mounts, environment, and other metadata.
[more information](D.Docker_Inspect.md)

---

```Docker
docker container logs <container>
```

shows the output generated by a container through its standard output and standard error.

---

```Docker
docker container logs -f <container>
```

shows the container logs and continuously follows new output as it is produced.

---

```Docker
docker exec <container> <command>
```

executes a command inside a running container.
[more_info](C.docker.exec.md)

---

```Docker
docker exec -it <container> <shell>
```

opens an interactive terminal inside a running container.

example:

```Docker
docker exec -it <container> bash
```

or:

```Docker
docker exec -it <container> sh
```

# Building Images

```Docker
docker build .
```

builds an image using the `Dockerfile` and files in the current directory as the build context.
[more_info](B.docker_build.md)

---

```Docker
docker build -t <image-name> .
```

builds an image and gives it a name/tag.

# Dockerfile

```Dockerfile
FROM <image>
```

specifies the base image that the new image will be built from.

---

```Dockerfile
WORKDIR <directory>
```

sets the working directory inside the image/container.

---

```Dockerfile
COPY <source> <destination>
```

copies files or directories from the build context into the image during the image build.

> NOTE
> 
> > `COPY` happens during `docker build`.
> > 
> > Changing the original file on the host after the image has been built does not change the copy inside the image.

---

```Dockerfile
RUN <command>
```

executes a command while the image is being built.

---

```Dockerfile
CMD ["<command>", "<argument>"]
```

specifies the default command that will be executed when a container is started from the image.

# Mounts

```Docker
docker run -v <host-path>:<container-path> <image>
```

creates a container with a bind mount connecting a path on the host machine to a path inside the container.

---

```Docker
docker run --mount type=bind,source=<host-path>,destination=<container-path> <image>
```

creates a container with a bind mount connecting a path on the host machine to a path inside the container.

example:

```Docker
docker run --mount type=bind,source=./image1/file.txt,destination=/app/file.txt image1
```

> NOTE
> 
> > A bind mount allows changes made to the mounted host file to be visible inside the container without rebuilding the image.

# Cleanup

```Docker
docker rm $(docker container ls -aq)
```

removes all containers returned by:

```Docker
docker container ls -aq
```

> ⚠️ NOTE
> 
> > This removes **all containers**, including stopped containers.
